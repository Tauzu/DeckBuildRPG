## 作業記録

### 2026-11-09（企画：ステージ制とチュートリアル）

- 何度も遊べるように、1人用のチュートリアルとステージ選択を入れることにした（企画書 12章）
  - チュートリアルをクリアするとステージ選択が解放される。ステージを進むほど、登場するカードと敵が増える
  - 今のカードを4ステージに分ける。ステージ1〜3とチュートリアルには専用のボスを新しく作る。その先は新しいカードで足す
  - 協力プレイでは、部屋を作った人が解放済みのステージから選ぶ。クリアすると全員の進み具合に反映
  - 進み具合はブラウザに保存（アカウントは作らない）
- 計画書：フェーズ4を「ステージ制」にし、マルチプレイはフェーズ5へ。全体は約18週→約22週

### 2026-11-09（バランス調整：2人以上）

- 敵の進軍を「全員の手番が終わるごと（1ラウンドに1回）」に戻した。ラウンドの全員が撃破したときだけ進軍しない（1人のときは今までと同じ）
- core に設定を追加：`marchTiming`（turn/round）、`marchSkip`（any/all/none）。状態に `roundDefeats`（そのラウンドで撃破した手番の数）
- 魔竜の生命力（2／3／4人）：40／45／50 → 62／105／150
- 結果（smart、200ゲーム）：2人53%、3人46%、4人47%（1人は52%のまま）
- 画面：遊び方の説明、戦闘中の「倒せる！」の注記、撃破直後のメッセージをラウンド制に合わせた
- 自動プレイ：人数ごとの数値を直接指定する候補（例：`bossHp_35_62_105_150`）
- テスト 71件（すべて成功）。仕様書 0.6 に更新
- 課題：2人以上では集落がほとんど傷つかない。ゲームが長い

### 2026-11-09（バランス調整：追加の3案を採用）

- 採用：英雄1人は食料なしで出せる、撃破直後のレベルアップ・転職、吟遊詩人Lv1は2枚引く
- 釣り合いのため：手札 6→5枚、魔竜の生命力 +5（1人35）
- 結果（1人、200ゲーム）：勝率 52〜53%、最初のレベルアップ 手番7.3→5.9
- 画面：撃破直後の段階（「手番を終える」ボタン、場と手札の英雄にLvアップ・転職ボタン）、英雄の枠の表示に無料の1枠を含める、遊び方の説明を更新
- 画面を実際に操作して確認：食料なしで英雄を1人出せる（枠 0/1→1/1）、撃破直後の段階と「手番を終える」、敵が進軍しないこと。エラーなし
- テスト 69件（すべて成功）。仕様書 0.5 に更新

### 2026-11-09（バランス調整：追加の3案の検討）

- テスト 66件（すべて成功）

### 2026-11-09（バランス調整：1人用）

- `packages/sim` を作成（自動プレイ）。ボット4種（smart／greedy／builder／passive）、候補の組み合わせを一括で比較、CSV 出力
- 調整前は勝率0%。手札で出せる最大ダメージがゲーム中ずっと3前後で、戦利品によるデッキの薄まりが主な原因と判明
- 採用した変更（詳細は「バランス調整.md」）
  - 手札 5→6枚、必要経験値 3/5→2/4、魔竜の生命力 +5
  - ルール追加：魔竜に与えたダメージは残る、戦利品は集落を訪れた手番の終わりに売却されて消える
- 結果（1人）：勝率 43〜49%、最初のレベルアップ 手番15→7、レベルアップ回数 2.4→9.7回
- core に設定項目を追加：`persistentDamage`（none/boss/all）、`sellLoot`、`lootToDeck`（調整用）
- 画面：魔竜の残り生命力の表示、ダメージ見込みに「これまでのダメージ」、戦利品の売却のログ、遊び方の説明を更新
- テスト 66件（すべて成功）。仕様書 0.4・企画書を更新
- 2人以上は勝率ほぼ0%。進軍の仕方を決める必要がある（要相談）

### 2026-11-08（遊んでみての改善）

- 行動の選び直し（「選び直す」ボタン）を追加
  - 集落：まだ何もしていなければ戻れる（カードを出す・購入・レベルアップ・転職をしたら戻れない）
  - 戦闘：攻撃を確定する前ならいつでも戻れる。出したカードは手札に戻る
- ルール変更：**敵を撃破した手番は進軍しない**（移動・進軍時の能力・公開をすべて行わない）
  - 戦闘中のダメージ見込みに「撃破すればこの手番は敵が進軍しない」と表示、ログにも表示
- テスト 62件（すべて成功）。画面でも、選び直しと撃破時に敵が進まないことを確認
- 仕様書（0.3）・企画書・設計書を更新
- バランスへの影響：撃破するたびに手番が増えるため、ゲームが長くなり、戦うほど有利になる。フェーズ3で確認する

### 2026-11-08（ソロ版の画面）

- `packages/client` を作成（React 19 + Vite 8 + Zustand 5）
  - `npm run dev` で起動、http://localhost:5173
- 設計書 4章のとおり、ゲームとのつなぎ口（`LocalConnection`）を通して core を動かす
- 画面：タイトル、遊び方、ゲーム、結果
  - 進軍ルート（敵をクリックして戦いを挑む）、村の在庫（クリックで購入）、記録（ログ）
  - 操作バー：段階の説明、所持金・英雄の枠、戦闘のダメージ見込み（耐性の内訳つき）、確定ボタン
  - 手札・場：クリックで出す、武器は選んでから英雄をクリックして装備、場のカードをクリックで手札に戻す
  - レベルアップ・転職のボタン、廃棄・手札を捨てる選択のダイアログ
  - できない操作は薄く表示し、理由を表示（core の `legalActions` の判定をそのまま使う）
  - 結果画面：勝敗、チーム評価、経験値・撃破数、記録（JSON）の保存
- ヘッドレスの Chrome で実際に操作して確認
  - 購入、戦闘（倒せなかった場合）、手札を捨てるダイアログ、敗北までの1ゲーム、コンソールのエラーなし
- 気づいたこと（バランス）：何もせず買い物だけしていると手番15ほどで集落が落ちる。序盤の戦い方が重要になりそう

### 2026-11-08（ルール実装）

- プロジェクトの土台を作成
  - npm workspaces、TypeScript 7（strict）、Vitest 5、Immer、Zod 4
  - `packages/core`（ルール本体）、`data/`（カードデータ JSON）
- カードデータを JSON 化（`data/heroes.json`・`items.json`・`enemies.json`・`setup.json`）
  - 読み込み時に Zod で形式を検証し、整合性（未定義ID、英雄のレベル抜け、ボスの数など）もチェック
- `core` にルールを実装
  - ゲームの準備（敵の山札の作り方、乱数のシード値）
  - 集落：村効果、購入、レベルアップ、転職、所持金の計算
  - 戦闘：食糧値による枠、武器の装備、出したカードの取り消し、耐性つきのダメージ計算
  - 敵の進軍：移動、集落への到達、進軍時・公開時の能力、手番ごとの進軍
  - 入力待ち（廃棄・手札を捨てる）と時間切れの代わりの操作
  - 勝敗・チーム評価・MVP・称号
  - できる操作の一覧（画面のボタン用）、見える情報の切り出し、記録からの再現
- テスト 55件（すべて成功）
  - 仕様書のダメージ計算の例、各ルール、ランダムに遊ばせての性質チェック（カード総数・uid の一意性・経験値）、再現、情報の秘匿
- 設計書との差分：進軍の段階を `move`（到達まで含む）／`onMarch`／`reveal`／`nextTurn` とした。設計書 2.4 を修正済み
