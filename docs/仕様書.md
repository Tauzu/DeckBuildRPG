## 1. 用語

| 用語 | 意味 |
|---|---|
| プレイヤー | ゲームに参加している人。1～4人 |
| 山札 | プレイヤーごとの、裏向きのカードの束。ここからカードを引く |
| 手札 | プレイヤーが持っているカード |
| 場 | 手番中にプレイしたカードを置く場所。手番の終わりに捨て札になる |
| 捨て札 | 使い終わったカードや、購入したカードが置かれる場所 |
| 廃棄 | カードをゲームから取り除くこと。廃棄したカードは二度と使わない |
| 村の在庫 | 購入できるカードの束。全員で共有する |
| 英雄在庫 | 村の在庫のうち、英雄ごとの束。レベルの低い順に上から積まれている |
| 進軍ルート | 敵が集落に向かって進む5マスの道。全員で共有する |
| 敵の山札 | 進軍ルートに出てくる敵カードの束 |
| 集落の耐久値 | 敵が集落に着くと減る値。0になると敗北 |
| 所持経験値 | レベルアップや転職に使える経験値。使うと減る |
| 総獲得経験値 | ゲーム中に得た経験値の合計。使っても減らない。MVPと称号の判定に使う |
| 手番 | 1人のプレイヤーが行動する番 |
| ラウンド | 全員が1回ずつ手番を行うまでの区切り。ラウンドが終わるたびに敵が1歩進軍する（1人なら手番＝ラウンド） |

## 2. カード

### 2.1 共通の項目

すべてのカードは次の項目を持つ。

| 項目 | 型 | 説明 |
|---|---|---|
| id | 文字列 | カードの種類を表すID（例：`hero_knight_2`）。同じ種類のカードは同じID |
| name | 文字列 | 表示名 |
| type | 種類 | `hero`（英雄）、`weapon`（武器）、`food`（食料）、`enemy`（敵）、`curse`（呪い） |
| cost | 整数 | 購入に必要な金額。購入できないカードは `null` |
| gold | 整数 | 金価値 |

ゲーム中の1枚1枚のカードには、上のIDとは別に **個体ID**（例：`c_0123`）を付けて区別する。

### 2.2 英雄カード

| 項目 | 型 | 説明 |
|---|---|---|
| heroId | 文字列 | 英雄の種類（例：`knight`）。レベル違いでも同じ |
| level | 整数 | レベル（村の若者は0とする） |
| physical | 整数 | 物理攻撃力 |
| magic | 整数 | 魔法攻撃力 |
| villageEffect | 村効果 | なければ `null` |
| nextLevelExp | 整数 | 次のレベルに必要な経験値。最大レベルなら `null` |

### 2.3 武器カード

| 項目 | 型 | 説明 |
|---|---|---|
| physical | 整数 | 物理攻撃力の補正 |
| magic | 整数 | 魔法攻撃力の補正 |

### 2.4 食料カード

| 項目 | 型 | 説明 |
|---|---|---|
| food | 整数 | 食糧値 |

### 2.5 敵カード

| 項目 | 型 | 説明 |
|---|---|---|
| hp | 整数 | 生命力。ボスは人数で変わる（6.2参照） |
| resistPhysical | 耐性 | 物理耐性：`none`（なし）、`half`（半減）、`immune`（無効） |
| resistMagic | 耐性 | 魔法耐性：同上 |
| exp | 整数 | 撃破時に得られる経験値 |
| invasion | 整数 | 集落に着いたときに減らす耐久値。ボスは `null` |
| isBoss | 真偽 | ボスかどうか |
| onReveal | 能力 | 公開されたときに発動する能力。なければ `null` |
| onMarch | 能力 | 進軍のたびに発動する能力。なければ `null` |

- 敵カードはプレイヤーのデッキに入っても **プレイできない**。金価値だけを持つ。

### 2.6 呪いカード

- 金価値0。プレイできず、何の効果もない。
- 呪いの在庫は **20枚**。在庫がなくなったら、呪いを加える効果は何もしない。

### 3.6 データファイル

カードデータは `data/` に JSON で置く。例：

```json
{
  "id": "hero_priest_3",
  "name": "僧侶",
  "type": "hero",
  "cost": 10,
  "gold": 1,
  "heroId": "priest",
  "level": 3,
  "physical": 2,
  "magic": 3,
  "villageEffect": { "kind": "trash", "count": 2 },
  "nextLevelExp": null
}
```

村効果・敵の能力は次の形で表す。

| 種類 | 形式 | 意味 |
|---|---|---|
| 村効果：カードを引く | `{ "kind": "draw", "count": 2 }` | 自分の山札からn枚引く |
| 村効果：金を増やす | `{ "kind": "gold", "amount": 2 }` | この訪問の所持金をn増やす |
| 村効果：経験値を得る | `{ "kind": "exp", "amount": 1 }` | 所持経験値と総獲得経験値をn増やす |
| 村効果：廃棄 | `{ "kind": "trash", "count": 2 }` | 自分の手札または捨て札から、n枚まで選んで廃棄する |
| 村効果：組み合わせ | `{ "kind": "multi", "effects": [ … ] }` | 書かれた順に実行する（吟遊詩人Lv3など） |
| 敵の能力：手札を捨てさせる | `{ "kind": "discardHand", "count": 1, "target": "all" }` | 対象のプレイヤーが手札をn枚選んで捨てる。target は `all`（全員）または `next`（次の手番のプレイヤー） |
| 敵の能力：呪いを加える | `{ "kind": "addCurse", "count": 1 }` | 全員の捨て札に呪いをn枚加える |

人数ごとの設定（敵の山札の枚数、集落の耐久値、ボスの生命力）も JSON で持つ。

## 4. ゲームの準備

1. 参加者の順番（手番順）を決める。ルームに入った順とする。
2. 各プレイヤーに初期デッキを配り、山札としてシャッフルする。
3. 各プレイヤーは山札から5枚引く（手札の枚数は `setup.json` の `handSize`）。
4. 所持経験値・総獲得経験値を0にする。
5. 村の在庫を並べる（3.1、3.2の枚数）。並べるのは、そのステージに登場する英雄と食料・武器だけ（4.3）。英雄在庫は、上からLv1→Lv2→Lv3の順に積む。
6. 集落の耐久値を、ステージと人数に応じて決める（4.3、6.2参照）。
7. 敵の山札を作る（4.1）。
8. 進軍ルートは空の状態で始める。
9. 手番順の1人目の手番から始める。

### 4.1 敵の山札の作り方

ステージと人数に応じた枚数（3.4、4.3）の敵カードを使う。

1. **序盤の束**：ステージで決めた敵（`earlyFull`。ゴブリン・灰色狼など）の全部と、`earlyHalf` の敵（スケルトン・亡霊など）をそれぞれ半分（端数切り捨て）。シャッフルする。
2. **終盤の束**：残りの敵カード全部。シャッフルする。
3. 終盤の束の上から2枚を取り、そのステージのボスと合わせてシャッフルする（**ボスの束**、3枚）。
4. 上から「序盤の束」「終盤の束の残り」「ボスの束」の順に重ねる。

## 5. ゲームの流れ

次をくり返す。

1. **プレイヤーの手番**：手番プレイヤーが手番を行う（5.1）。
2. **敵の進軍**：最後のプレイヤーの手番が終わったら（＝ラウンドの終わりに）、敵が1歩進軍する（5.4）。ただし **そのラウンドの全員が敵を撃破した場合は進軍しない**。
3. 勝敗が決まっていなければ、手番順で次のプレイヤーの手番へ進む（最後のプレイヤーの次は1人目に戻る）。

- **1ラウンドに1回** 進軍する（`setup.json` の `marchTiming`：`round`）。1人なら毎手番の後に進軍し、撃破した手番は進軍しない。
- 進軍をやめる条件は `marchSkip`：`all`（ラウンドの全員が撃破したとき）。

### 5.1 手番

手番プレイヤーは、次のどちらか1つを選ぶ。

- **集落を訪れる**（5.2）
- **敵を倒す**（5.3）。進軍ルートに敵がいないときは選べない。

#### 行動の選び直し
- 次の場合は「選び直す」で行動の選択に戻れる（`cancelAction`）。
  - 集落：まだ何もしていない（カードを出す・購入・レベルアップ・転職のどれもしていない）
  - 戦闘：攻撃を確定する前。出したカード・装備した武器はすべて手札に戻る
- 選び直した後は、どちらの行動を選んでもよい（別の敵に挑んでもよい）。

選んだ行動が終わったら **手番の終了処理** を行う。

1. 手札と場のカードをすべて捨て札にする。
2. 山札から5枚引く。
3. ラウンドの最後の手番なら、敵の進軍へ進む。

#### カードを引くときの処理
- 山札がなくなったら、捨て札をシャッフルして新しい山札にし、続けて引く。
- 山札も捨て札もなくなったら、それ以上は引かない（引ける分だけ引く）。

### 5.2 集落を訪れる

訪問中は、次の操作を **好きな順番で何度でも** 行える。「訪問を終える」を選ぶと終了する。

訪問を終えるとき、**手札に残っている敵カード（戦利品）は売却され、ゲームから取り除かれる**（金として使ったものとみなす。`setup.json` の `sellLoot`）。戦利品はデッキに1周だけ混ざり、お金になって消える。

#### 所持金
- 所持金 ＝（手札と場のカードの金価値の合計）＋（村効果で増えた金）−（この訪問で使った金）
- 手札や場のカードが減る操作（廃棄、レベルアップなど）は、その後の所持金が0未満になる場合は行えない。

#### (a) 食料をプレイする
- 手札の食料カードを場に出す。食糧値が「英雄を出せる枠」に加わる。
- 英雄を出せる枠は、食料を出していなくても **1つある**（`setup.json` の `freeHeroSlots`）。つまり英雄は「1人＋食糧値の合計」まで出せる。集落でも戦闘でも同じ。

#### (b) 英雄をプレイして村効果を使う
- 手札の英雄カードを場に出す。英雄を出せる枠を1つ使う。
- 枠が残っていなければ出せない。
- 村効果を持つ英雄なら、出したときに村効果を実行する。村効果を持たない英雄も出すことはできる（効果はない）。

#### (c) 購入する
- 村の在庫の束から、一番上のカードを1枚選び、コスト分の金を使って自分の捨て札に加える。
- 所持金がコストより少なければ買えない。
- 購入枚数に上限はない。

#### (d) レベルアップする
- 条件：
  - 手札に英雄カード（村の若者以外）がある
  - その英雄が最大レベルではない
  - 所持経験値がその英雄の「次のレベルに必要な経験値」以上ある
  - その英雄在庫に、1つ上のレベルのカードが残っている
- 処理：
  1. 所持経験値を必要な分だけ減らす
  2. 手札のその英雄カードを廃棄する
  3. 英雄在庫から1つ上のレベルのカードを1枚取り出し、捨て札に加える（上に低いレベルのカードが残っていても取り出せる）

#### (e) 転職する
- 条件：手札に村の若者がある、所持経験値が2以上、選んだ英雄の在庫にLv1が残っている
- 処理：所持経験値を2減らし、村の若者を廃棄し、選んだ英雄のLv1を在庫から取り出して捨て札に加える

#### 補足
- 集落では、場に出した英雄はレベルアップ・転職に使えない（手札にあるものだけが対象）。
- 敵を撃破した直後にもレベルアップ・転職ができる（5.3.2）。
- 武器カードは訪問中にはプレイできない（金価値としてだけ使う）。

### 5.3 敵を倒す

1. **敵を選ぶ**：進軍ルート上の敵から1体を選ぶ。
2. **カードを出す**：次の操作を好きな順番で行う。
   - 手札の食料カードを場に出す（英雄を出せる枠が増える）
   - 手札の英雄カードを場に出す（枠を1つ使う）
   - 手札の武器カードを、場の英雄1枚に装備する。1人の英雄に装備できる武器は1枚まで。装備した武器は付け替えられない
   - 英雄がいなくても使える武器（`solo`）は、装備せずにそのまま場に出せる
3. **攻撃を確定する**：確定する前なら、手順2で出したカードを手札に戻してやり直せる。行動の選び直しもできる（5.1）。
4. **ダメージを計算する**（5.3.1）。
5. **結果**：
   - ダメージが敵の生命力 **以上** なら撃破（5.3.2）。
   - そうでなければ撃破失敗。敵はそのまま残る。
   - **ボスに与えたダメージは残り**、次の攻撃のダメージに足される（`setup.json` の `persistentDamage`：`boss`）。ボス以外の敵のダメージは残らない。

#### 5.3.1 ダメージの計算

1. 物理の合計 ＝ 場の英雄の物理攻撃力と、装備した武器の物理補正（レベルで増える分を含む）、装備せずに出した武器の物理補正をすべて足したもの
2. 魔法の合計 ＝ 同様に魔法をすべて足したもの
3. 敵の耐性を合計に対して適用する。ただし、耐性を受けない武器（`pierce`）を装備した英雄の攻撃は、合計から除いておく
   - 半減：2で割って端数を切り捨てる
   - 無効：0にする
4. ダメージ ＝ 耐性適用後の物理の合計 ＋ 耐性適用後の魔法の合計 ＋ 耐性を受けない攻撃の物理と魔法

例：騎士Lv1（物理3）＋鉄の剣（物理+3）と、狩人Lv1（物理2・魔法1）でスケルトン（物理半減）を攻撃
→ 物理 3+3+2=8 → 半減で4、魔法1 → ダメージ5（スケルトンの生命力5に届いて撃破）

#### 5.3.2 撃破

1. 敵カードを進軍ルートから取り除き、手番プレイヤーの捨て札に加える。
2. 手番プレイヤーの所持経験値と総獲得経験値に、敵の経験値（と、撃破で経験値が増える武器の分）を加える。
3. ボスを撃破した場合は、その時点で **勝利**（7章）。
4. **撃破直後のレベルアップ**：ボス以外を撃破したら、手番を終える前に、場の英雄（戦った英雄）と手札の英雄をレベルアップ・転職できる（条件と処理は5.2(d)(e)と同じ。所持金の条件はない）。終えると手番が終わる（撃破した手番として5.4の判定に数える）。（`setup.json` の `levelUpAfterBattle`）

### 5.4 敵の進軍

- ラウンドの終わりに行う。**そのラウンドの全員が敵を撃破した場合は、進軍を丸ごと行わない**（移動・進軍時の能力・公開のどれも行わない）。それ以外は、次の順に処理する。

1. **移動**：進軍ルート上のすべての敵が1マス進む。5マス目にいた敵は集落に着く。
2. **集落への到達**：集落に着いた敵ごとに、
   - ボスなら、その時点で **敗北**。
   - それ以外なら、侵攻力の分だけ集落の耐久値を減らし、その敵をゲームから取り除く。耐久値が0以下になったら、その時点で **敗北**。
3. **進軍時の能力**：進軍ルート上の敵の「進軍時」の能力を、集落に近い敵から順に発動する。
4. **公開**：敵の山札から1枚公開し、進軍ルートの1マス目に置く。その敵の「公開時」の能力を発動する。敵の山札がなければ何もしない。

- 1つのマスに何体でも敵がいてよい。
- 公開されたばかりのボスは、その回の「進軍時」の能力は発動しない（3より4が後のため）。次の進軍から発動する。

### 5.5 敵の能力の処理

- **手札を捨てる**：対象のプレイヤー（全員、または次の手番のプレイヤー）が、自分の手札から指定の枚数を選んで捨て札にする。手札が足りなければ、ある分だけ捨てる。
  - 対象が複数いるときは同時に選ぶ。30秒以内に選ばなければ、ランダムに選ばれる。
  - 「次の手番のプレイヤー」は、ソロでは自分自身になる。
- **呪いを加える**：全プレイヤーの捨て札に、呪いの在庫から指定の枚数を加える。手番順に1枚ずつ配り、在庫がなくなったらそこで終わる。

### 6.1 共有するもの・個人のもの

| 全員で共有 | プレイヤーごと |
|---|---|
| 村の在庫、呪いの在庫、進軍ルート、敵の山札、集落の耐久値 | 山札、手札、場、捨て札、所持経験値、総獲得経験値 |

### 6.2 人数ごとの設定

| 人数 | 敵の山札（ボス除く） | 集落の耐久値 | ボスの生命力 |
|---|---|---|---|
| 1人 | 18 | 15 | 40 |
| 2人 | 24 | 15 | 69 |
| 3人 | 30 | 20 | 113 |
| 4人 | 36 | 20 | 165 |

- この表はステージ4の値。ほかのステージは4.3。
- 敵はラウンドごとに進むため、人数が増えても1人あたりの手番の数は変わらない。全員で魔竜を削るので、魔竜の生命力を人数に応じて大きくしている。

### 6.3 見える情報

| 情報 | 自分 | 他のプレイヤー |
|---|---|---|
| 手札 | 見える | 枚数だけ見える |
| 山札 | 枚数だけ見える | 枚数だけ見える |

| 場・経験値 | 見える | 見える |

### 6.4 協力のしかた

- 他のプレイヤーの戦闘に加わる手段（援護・共同攻撃）は **今の版では用意しない**。戦闘は手番プレイヤーが1人で行う。
- 協力は「誰がどの敵を倒すか」「誰が村で育成に回るか」を話し合うことで行う。
- 援護は、ルールが複雑になるため一旦見送る。基本のルールで遊んでみて、協力の手応えが足りなければ改めて検討する。

### 7.1 勝敗

| 結果 | 条件 | 判定のタイミング |
|---|---|---|

|---|---|
| S | 勝利し、集落の耐久値が初期値の80%以上残っている |

|---|---|

| 2位 | 聖騎士 |

- ソロでは MVP と称号は表示せず、チーム評価と総獲得経験値だけを表示する。

## 8. プログラムの構成

### 8.1 ゲーム状態

`core` パッケージで扱うゲーム状態の主な内容（TypeScript の型の例）。

```ts
type GameState = {
  seed: number;
  rngState: number;                  // 乱数の現在の状態
  phase: "playerTurn" | "enemyMarch" | "waiting" | "finished";
  turnCount: number;                 // これまでの手番の数
  currentPlayerIndex: number;
  players: PlayerState[];
  village: {
    heroStacks: Record<HeroId, CardInstance[]>;   // 先頭が一番上
    otherStacks: Record<CardId, CardInstance[]>;  // 食料・武器
    curses: CardInstance[];
  };
  enemyDeck: CardInstance[];         // 先頭が一番上
  route: CardInstance[][];           // route[0] が1マス目、route[4] が5マス目
  villageHp: number;
  turn: TurnState | null;            // 手番中の一時的な状態
  pending: PendingChoice | null;     // 手札を捨てる選択や廃棄の選択など、入力待ち
  result: { outcome: "win" | "lose"; rank: "S" | "A" | "B" | "C" } | null;
  log: LogEntry[];
};

type PlayerState = {
  id: string;
  name: string;
  deck: CardInstance[];
  hand: CardInstance[];
  field: CardInstance[];
  discard: CardInstance[];
  exp: number;          // 所持経験値
  totalExp: number;     // 総獲得経験値
  kills: number;        // 撃破数
};

type TurnState =
  | { action: "village"; foodSlots: number; usedSlots: number; bonusGold: number; spentGold: number; acted: boolean }
  | { action: "battle"; targetId: string; foodSlots: number; usedSlots: number;
      equips: Record<string, string> };          // 英雄の個体ID → 武器の個体ID
```

### 8.2 操作

ゲームの進行は、すべて次の「操作」を `core` に渡して行う。`core` は操作が正しいかを確かめ、正しければ新しいゲーム状態を返し、正しくなければエラーを返す。

| 操作 | 内容 | 行える人・タイミング |
|---|---|---|
| `chooseVillage` | 集落を訪れる | 手番プレイヤー・手番のはじめ |
| `chooseBattle(targetId)` | 敵を選んで戦う | 手番プレイヤー・手番のはじめ |
| `cancelAction` | 行動を選び直す | 手番プレイヤー・訪問中（まだ何もしていない）／戦闘中（確定前） |
| `playFood(cardId)` | 食料を場に出す | 手番プレイヤー・訪問中／戦闘中 |
| `playHero(cardId)` | 英雄を場に出す（訪問中なら村効果を実行） | 手番プレイヤー・訪問中／戦闘中 |
| `resolveTrash(cardIds)` | 廃棄するカードを選ぶ（0枚でもよい） | 手番プレイヤー・廃棄の村効果の後 |
| `buy(stackId)` | 在庫から購入する | 手番プレイヤー・訪問中 |
| `levelUp(cardId)` | レベルアップする | 手番プレイヤー・訪問中 |
| `changeClass(cardId, heroId)` | 転職する | 手番プレイヤー・訪問中 |
| `equip(weaponId, heroId)` | 武器を装備する | 手番プレイヤー・戦闘中 |
| `undoBattleCard(cardId)` | 出したカードを手札に戻す | 手番プレイヤー・戦闘中（確定前） |
| `confirmAttack` | 攻撃を確定する | 手番プレイヤー・戦闘中 |
| `endVisit` | 訪問を終える | 手番プレイヤー・訪問中 |
| `discardForEffect(cardIds)` | 敵の能力で手札を捨てる | 能力の対象のプレイヤー |

- 手番の終了処理と敵の進軍は、操作がなくても `core` が自動で進める。
- 入力待ち（`pending`）がある間は、その入力以外の操作は受け付けない。
- 30秒の制限時間はサーバー（ソロではブラウザ）が計り、時間切れのときに代わりの操作を `core` に渡す。

### 8.3 ログ

- すべての操作と、その結果起きたこと（引いたカード、敵の移動、撃破など）をログに残す。
- ログは画面の履歴表示と、バランス調整用の記録に使う。
- シード値と操作の一覧があれば、ゲームを最初から再現できるようにする。

## 9. 通信（マルチプレイ）

### 9.1 方針

- ゲーム状態は **サーバーだけ** が持つ。ブラウザは操作を送り、サーバーから届いた状態を表示するだけにする。
- サーバーは、各プレイヤーに **そのプレイヤーが見てよい情報だけ** を送る（6.3）。他人の手札の中身や山札の順番は送らない。

### 9.2 ルーム

- ルームを作ると、6文字のルームコード（英大文字と数字）が発行される。
- 他のプレイヤーはルームコードを入力して参加する。最大4人。
- ルームを作った人（ホスト）が「開始」を押すとゲームが始まる。1人でも開始できる。
- ゲーム開始後は新しく参加できない。
- ステージはホストが、自分が解放したステージから選ぶ。そのステージで遊べる人数でなければ開始できない（チュートリアルは1人用）。
- 勝利すると、そのステージのクリアが参加者全員の進み具合（各自のブラウザ）に記録される。
- 待機中に接続が切れた人はルームから外れる（ゲーム中は9.4のとおり席を残す）。

### 9.3 メッセージ

| 向き | 名前 | 内容 |
|---|---|---|
| ブラウザ → サーバー | `room:create` | プレイヤー名、ステージ |
| ブラウザ → サーバー | `room:join` | ルームコード、プレイヤー名 |
| ブラウザ → サーバー | `room:resume` | ルームコード、トークン（再接続） |
| ブラウザ → サーバー | `room:setStage` | ステージ（ホストのみ、開始前） |
| ブラウザ → サーバー | `room:start` | なし（ホストのみ） |
| ブラウザ → サーバー | `room:backToLobby` | なし（ホストのみ、結果が出たあと。同じ顔ぶれで待機に戻る） |
| ブラウザ → サーバー | `room:leave` | なし |
| ブラウザ → サーバー | `game:action` | 操作（8.2）とその引数 |
| サーバー → ブラウザ | `room:update` | ルームの参加者一覧 |
| サーバー → ブラウザ | `game:state` | そのプレイヤー向けのゲーム状態 |
| サーバー → ブラウザ | `game:error` | 操作が受け付けられなかった理由 |

### 9.4 接続が切れたとき

- 接続が切れても、プレイヤーの席は **5分間** 残す。同じブラウザから再接続すれば続きから遊べる。
- 接続が切れている人の手番や入力待ちは、制限時間が来たら次のように自動で進める。
  - 手番：「集落を訪れる」を選び、何もせずに終える
  - 手札を捨てる：ランダムに選ぶ
- 5分を過ぎても戻らなければ、以後その人の手番は同じ方法で自動で進める。
- つながっているのに **60秒** 何も操作しない人の手番も、同じ方法で代わりに進める（操作するたびに数え直す）。これが **2回続く** と、以後その人は自動で進める（画面に「自動」と出る）。本人が操作すれば手動に戻る。
- 手番の画面に「あと◯秒で、操作がないと代わりに進みます」を出す（残り10秒で赤）。サーバーが更新に残り時間（`timeLeftMs`）を載せ、ブラウザは受け取った時点から数える（時計のずれを避けるため）。

| 遊び方 | ルールの説明 |

### 10.2 ゲーム画面の構成

| 場所 | 表示するもの |
|---|---|
| 上部 | 進軍ルート（5マス、敵カード）、敵の山札の残り枚数、集落の耐久値 |
| 中央 | 村の在庫（英雄在庫6束、食料4束、武器6束。各束の一番上と残り枚数） |
| 下部 | 自分の手札、場、山札と捨て札の枚数、所持経験値・総獲得経験値 |
| 横 | 他のプレイヤーの情報（名前、手札の枚数、経験値、手番かどうか）、ログ |
| ボタン | 「集落を訪れる」「敵を倒す」「攻撃を確定」「訪問を終える」など、今できる操作だけを表示 |

- 戦闘中は、選んだ敵の生命力・耐性と、今のカードで出せるダメージの見込みを常に表示する。
- 訪問中は、今の所持金と、英雄を出せる枠の残りを常に表示する。
- できない操作（金が足りない購入など）は押せない状態で表示し、理由がわかるようにする。
