# FOODIE QUEST

**エルムの村のはらぺこ英雄たち**

1～4人で遊べる、デッキビルド × RPG の協力型ブラウザゲーム。
魔竜の軍勢が集落に届く前に、英雄たちを育ててボスを討つ。

## 遊ぶまでの手順

### 1. 準備（最初の1回だけ）

[Node.js](https://nodejs.org/)を入れてから（バージョン 24 で動作を確認）、このフォルダで次を実行する。

```sh
npm install
```

### 2. 起動する

目的に合わせて、ターミナルでコマンドを実行する。止めるときは、そのターミナルで `Ctrl + C`。

| やりたいこと | 起動するもの | 開くアドレス |
|---|---|---|
| 1人で遊ぶ | `npm run dev` | http://localhost:5173 |
| みんなで遊ぶ（協力プレイ） | `npm run dev` と `npm run dev:server` の**2つ**（ターミナルを2つ開く） | http://localhost:5173 |
| スマートフォンで遊ぶ | `npm run dev:lan`（協力プレイもするなら `npm run dev:server` も） | 起動時に表示される `Network: http://192.168.…:5173` |
| 公開するときの形で動かす | `npm start` | http://localhost:3000 |

- `npm run dev` と `npm run dev:lan` は同じ画面を出す。`dev:lan` は同じWi‑Fiの他の機器からも開ける。どちらか一方だけを起動する
- `npm run dev:server` は協力プレイの通信を受け持つサーバー（ポート3000）。画面（ポート5173）が通信をここへ中継するので、ブラウザで開くのは 5173 のほう
- スマートフォンから開けないとき：パソコンとスマートフォンが同じWi‑Fiにつながっているか確認する。Windows のファイアウォールが許可を求めてきたら「プライベートネットワーク」で許可する
- `npm start` は画面を組み立て（ビルド）、サーバー1台で画面と協力プレイの両方を配信する。ポートは環境変数 `PORT` で変えられる
- 起動中にプログラムを書き換えると、画面とサーバーは自動で更新される（`npm start` を除く）

### 3. 協力プレイの始め方

1. タイトルで「みんなで遊ぶ」→ 1人が「ルームを作る」
2. 表示された6文字のルームコードを他の人に伝え、他の人は「参加する」で入力する
3. 全員そろったら、ルームを作った人がステージを選んで開始する

## 開発用のコマンド

```sh
npm test            # テスト
npm run typecheck   # 型チェック
npm run build       # 画面を組み立てる（packages/client/dist）
npm run sim -- --players 1 --games 200   # 自動プレイ（バランス調整用）
```

## 公開用のイメージ（Docker）

```sh
docker build -t deckbuild-rpg .
docker run -p 3000:3000 deckbuild-rpg   # http://localhost:3000
```

- 動作の確認用に `/healthz`（`ok` を返す）がある
- 環境変数：`PORT`（既定 3000）、`MAX_ROOMS`（同時に存在できるルームの数。既定 200）

## 公開（Render）

[Render](https://render.com/) の無料枠で公開する。設定は `render.yaml` に書いてある（シンガポール、無料、`main` に push すると自動で公開し直す）。

### 最初の1回

1. Render にアカウントを作る（GitHub のアカウントで登録できる）
2. ダッシュボードで **New → Blueprint** を選び、GitHub の `Tauzu/DeckBuildRPG` をつなぐ
3. `render.yaml` の内容が表示されるので、そのまま **Apply**（作成）
4. 組み立てと起動が終わると、`https://foodie-quest-xxxx.onrender.com` のようなアドレスが発行される

### そのあと

- `main` に push するたびに、自動で組み立てて公開し直す（数分かかる）
- 動いているかは `https://（発行されたアドレス）/healthz` が `ok` を返すかで分かる

### 無料枠で気をつけること

- 15分だれも使わないと止まる。次に開いた人は、起動まで1分ほど待つ（協力プレイの通信が続いている間は止まらない）
- 止まったり公開し直したりすると、協力プレイのルームは消える（1人プレイと進み具合はブラウザ側なので消えない）
- 通信量・稼働時間に上限がある。1人が初めて開くときの通信量は約0.4MB（圧縮して送る。ゲーム画面まで）。2回目からはブラウザに残った分を使う
- 止まらないようにしたいときは、有料（月7ドル程度）に切り替える

## フォルダの構成

| フォルダ | 内容 |
|---|---|
| `packages/core` | ルール本体（画面にもサーバーにも依存しない） |
| `packages/client` | 画面（React + Vite） |
| `packages/server` | 協力プレイのサーバー（Socket.IO） |
| `packages/sim` | 自動プレイ（バランス調整） |
| `data/` | カード・ステージのデータ（JSON） |
| `docs/` | ドキュメント |
